# Состояние репозитория

Ответь на вопрос «где я сейчас и что у меня подвисло», а потом предложи с этим что-то сделать.

Команда написана для работы **без git-интерфейса**: пользователь не видит ни текущей ветки,
ни незакоммиченных правок, ни того, что накопилось за прошлые сессии. Всё, что он знает
о репозитории, он знает от тебя. Поэтому очевидное — тоже говори.

## Шаг 1. Снять состояние

Выполни скилл `git-inventory` и получи факт-лист. Не начинай с выводов: сначала данные.

## Шаг 2. Отсортировать по риску потери

Категория «тип объекта» пользователю бесполезна — ветки, стеши и незакоммиченное валятся
в одну кучу. Полезная сортировка одна: **что исчезнет, если этот диск умрёт прямо сейчас.**

| Уровень | Что сюда попадает | Почему так |
|---|---|---|
| **Только здесь** | незакоммиченное и неотслеживаемое; коммиты на ветках без upstream; всё, что в стешах; незакоммиченное в worktree; коммиты в detached HEAD | Существует в одном экземпляре. Копии нет нигде |
| **Мешает** | незапушенные коммиты на ветке с upstream; отставание от базы; незавершённая операция (rebase, merge, cherry-pick) | Не пропадёт, но врёт о состоянии работы или блокирует следующий шаг |
| **Мусор** | ветки, слитые по `git cherry`; ветки с `[gone]` upstream; стеши, содержимое которых уже в базе | Ничего не теряется при удалении, но копится и мешает разглядеть остальное |

Внутри «Только здесь» сортируй по объёму работы, а не по дате: тридцать несохранённых файлов
важнее одного коммита без upstream.

**Ветка без upstream и `[gone]` — это разные вещи, которые легко перепутать.** Первая никогда
не пушилась: её содержимое уникально. Вторая пушилась, а потом удалена на origin — почти всегда
потому, что PR слит. Первую трогать нельзя, вторую можно удалять.

## Шаг 3. Отчёт

Начинай с того, где пользователь находится, — даже если там всё чисто. Это главный вопрос,
ради которого команду и запускают.

```
## Репозиторий <имя>

Ты на ветке: <ветка> — последний коммит <когда>, <ahead/behind или «совпадает с origin»>
База: <ветка> | <если идёт rebase/merge — сказать это здесь, первой строкой и жирным>

### Существует только на этом диске
- <что именно, объём, где лежит>
- (или: ничего — всё, что есть, отправлено на origin)

### Мешает
- <незапушенное, отставание, застрявшая операция>

### Можно убрать
- <слитые ветки, [gone], мёртвые стеши>

### Ветки
| Ветка | Состояние | PR | Последний коммит |
|---|---|---|---|
| <имя> | слита / в работе / никогда не пушилась / origin удалён | #N или — | <когда> |

### Не удалось проверить
- <что и почему: нет gh, нет сети, нет доступа>
```

Правила отчёта:

- **Чисто — так и скажи, коротко.** Пустой отчёт из шести заголовков «ничего не найдено» хуже
  двух строк «ты на такой-то ветке, всё запушено, ничего не висит».
- **Ветку показывай всегда.** Даже если она ожидаемая. Пользователь не может её увидеть.
- **Возраст — относительный** («31 час назад»), не даты: они требуют устного вычитания.
- **Не пересказывай `git status`.** Пользователю нужно «три файла с правками в backend»,
  а не выгрузка порцелайна.

## Шаг 4. Предложить действия

После отчёта — конкретные предложения, по одному на находку. Не общий вопрос «что делаем?»,
а список, из которого можно выбрать номерами.

Формулируй как действие с последствием: не «удалить ветку», а «удалить `<имя>` локально
и на origin — она слита в main, ничего не потеряется».

| Находка | Что предложить |
|---|---|
| Незакоммиченное | Показать дифф; закоммитить (`/ship` соберёт сообщение и PR) |
| Неотслеживаемый файл | Добавить и закоммитить, либо внести в `.gitignore` — сначала посмотреть, что это |
| Коммиты без upstream | Запушить с `-u` — это снимает единственную копию с одного диска |
| Ветка `[ahead]` | Запушить |
| Слитая ветка | Удалить локально (`git branch -d`) и на origin |
| Ветка `[gone]` | Проверить, нет ли своих коммитов, затем удалить локально |
| Стеш | Показать содержимое; после этого — применить или удалить |
| Незавершённая операция | Показать, где остановилась; продолжить или прервать — решает пользователь |
| Забытая ветка с открытым PR | Ничего не удалять: работа ждёт ревью. Просто назвать её |

Выполняй **только то, что пользователь подтвердил**. Не пакетом «сделал всё, что было
безопасно» — по пунктам, которые он выбрал.

## Чего не делать никогда

Эта команда существует, чтобы работа не терялась. Значит она сама не имеет права стать
причиной потери. Ни одна уборка не стоит чужого несохранённого дня.

**Не выполняй по своей инициативе, ни при каких обстоятельствах:**

```
git reset --hard        git checkout -- .       git clean -fd
git stash drop          git stash clear         git stash pop (без показа содержимого)
git branch -D           git push --force        git rebase (в чужую сторону)
```

Если пользователь просит явно — выполняй, но сначала одной строкой покажи, что именно
исчезнет и есть ли этому копия. Просьба «прибери тут» явной не является.

Три отдельных правила:

- **`git branch -d`, а не `-D`.** Строчная форма откажется удалять ветку с неслитыми
  коммитами — это и есть нужная страховка. Отказ означает «я ошибся, там что-то есть»,
  а не «надо взять флаг посильнее».
- **Стеш не удаляется, пока его содержимое не показано.** Даже старый, даже с давно слитой
  ветки. Имя стеша не говорит о содержимом ничего.
- **Не коммить за пользователя молча.** Незакоммиченные правки могут быть незаконченным
  экспериментом. Коммит — это его решение; собрать сообщение поможет `/ship`.

## Границы

Команда смотрит **только текущий репозиторий** — тот, в котором запущена. Другие проекты
на машине её не касаются.

Она отвечает на вопрос «в каком состоянии репозиторий», а не «хорош ли код». Что не так
с изменениями — это `/agent-full-review`. Почему код такой — `/debug`. Отправить работу —
`/ship`.
