# Аудит CLAUDE.md

Файл в контексте каждой сессии, поэтому устаревшее в нём не просто бесполезно — оно **активно
вредит**: агент верит написанному и принимает решения на ложных основаниях.

## Что проверять

### 1. Пути и файлы

Каждый упомянутый путь должен существовать. Переехавшие модули — самая частая причина протухания.

```bash
grep -oE '`[^`]*/[^`]*`' CLAUDE.md | tr -d '`' | while read -r p; do
  [ -e "$p" ] || echo "НЕТ: $p"
done
```

Проверяй и обратное: описан ли раздел, которого больше нет, и не появилась ли крупная часть
проекта, о которой файл молчит (новое приложение в монорепо, новый сервис).

### 2. Команды

Упомянутые команды должны работать. Сверь с реальными точками входа — скиллом `detect-tooling`.
Классика: в файле `npm run test`, а в проекте всё идёт через `make test` в контейнере.

### 3. Утверждения против кода

Самое ценное и самое трудоёмкое. Возьми конкретные заявления и проверь выборочно:

- «токены только в защищённом хранилище» — а в коде запись в обычное;
- «суммы считает сервер» — а клиент отправляет `amount`;
- «все строки через словари» — а в новых экранах хардкод;
- «на каждый эндпоинт есть тест» — а последние три без тестов.

Расхождение может означать две разные вещи, и это важно различать: **правило устарело**
(и файл надо править) либо **код нарушает живое правило** (и это находка для ревью). Не решай
сам — покажи оба варианта.

### 4. Объём

Ориентир — 60–100 строк. Разросшийся файл обычно означает, что в него натаскали выводимого
из кода. Отметь разделы-кандидаты на сокращение: перечисления файлов, пересказ основ фреймворка,
общие пожелания.

### 5. Дублирование картриджей

Если в файле пересказаны правила фреймворка, которые и так знает картридж стека, — это лишнее.
`CLAUDE.md` про **этот проект**, а не про Laravel вообще.

## Отчёт

```
## Аудит CLAUDE.md

Объём: N строк (~M слов) — в норме / великоват

### Не существует
- `путь` — упомянут в разделе «...»

### Команды не совпадают
- В файле: `...` | Фактически: `...`

### Код противоречит написанному
- Утверждение: «...»
  Код: file:line — ...
  Это устаревшее правило или нарушение живого? — требует решения

### Не описано, а стоило бы
- <новая часть проекта / изменившийся контракт>

### Кандидаты на сокращение
- Раздел «...» — выводится из кода / дублирует картридж <какой>

### Итог
- Расхождений: N | Пропусков: N | Строк можно убрать: ~N
```

Ничего не правь сам — аудит только сообщает. Правки делает `/context-refresh` с подтверждения
пользователя.
