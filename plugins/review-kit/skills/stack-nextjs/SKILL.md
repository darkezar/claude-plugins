# Картридж: Next.js

Подключается, когда в `dependencies` есть `next`. Версию и роутер определи по факту: наличие
`app/` — App Router, `pages/` — Pages Router, встречается и то и другое одновременно. Многие
правила ниже применимы только к App Router — не тащи их в Pages-проект.

## Тулинг

```bash
npx tsc --noEmit        # типы, если TypeScript
npm run lint            # обычно next lint / eslint
npm run build           # ловит ошибки границ server/client и пререндера
```

Перед запуском проверь, какие скрипты реально есть в `package.json` — не вызывай наугад.

## Триггеры условных ревьюеров

**auth** — пути: `middleware.ts`, `app/api/**`, `pages/api/**`, `app/(auth)/**`, `lib/auth*`,
`auth.ts`/`auth.config.ts`, server actions (`'use server'`), `app/**/layout.tsx` с проверками сессии.
Слова в дифе: `NextAuth`, `auth()`, `getServerSession`, `cookies()`, `headers()`, `jwt`, `session`,
`middleware`, `redirect(`, `'use server'`, `Authorization`, `csrf`, `NEXT_PUBLIC_`.

**performance** — слова в дифе: `useEffect` с фетчем, `'use client'` на крупных ветках дерева,
`fetch(` с `cache`/`revalidate`, `dynamic = 'force-dynamic'`, `<img`, `next/image`, `next/dynamic`,
`useMemo`/`useCallback`, большие массивы в рендере, новые тяжёлые зависимости в `package.json`.

## Привязки чек-листа

### Безопасность
- **`NEXT_PUBLIC_` = публично.** Любой секрет под этим префиксом уезжает в клиентский бандл и
  извлекаем. Ключи API, токены сервисов, строки подключения — только без префикса и только
  в серверном коде.
- **Секрет в клиентском компоненте.** Файл с `'use client'` (и всё, что он импортирует) попадает
  в бандл. Импорт серверного модуля с ключами в клиентский компонент — утечка.
- Server action (`'use server'`) — это **публичный эндпоинт**. Каждый обязан сам проверять
  аутентификацию и права: вызвать его можно напрямую, минуя UI, который его «прячет».
- Route handler в `app/api/**` — то же самое: проверка прав внутри хендлера, а не в UI.
- SSRF: `fetch(userProvidedUrl)` на сервере без allowlist схемы и хоста.
- Открытый редирект: `redirect(searchParams.next)` без whitelist.
- Инъекции: сырой SQL с шаблонными строками (`sql\`...${userInput}\``, конкатенация в Prisma
  `$queryRawUnsafe`) → параметризация.
- Утечка в RSC-пейлоаде: серверный компонент передаёт клиентскому пропсом целую модель
  (с хэшем пароля, внутренними полями) — сериализуется и уезжает в браузер.
- `dangerouslySetInnerHTML` на пользовательских данных без санитизации.
- Заголовки безопасности и CORS на route handlers: `Access-Control-Allow-Origin: *` на приватных ручках.

### Авторизация и доступ
- Проверка сессии в `middleware.ts` — **не** полноценная защита данных: она про навигацию.
  Авторитет — проверка внутри route handler / server action / серверного запроса к БД.
- `layout.tsx` с редиректом гостя защищает рендер, но не защищает API-роут под тем же путём.
- IDOR: запрос к БД по `id` из `params`/`searchParams`/тела без скоупа по владельцу.
- Server action принимает `userId`/`role`/сумму из аргументов и доверяет им.
- Cookie сессии: `httpOnly`, `secure`, `sameSite`; срок жизни и реальный отзыв при logout.
- Rate limit на login/OTP/восстановление — на уровне route handler или edge middleware.

### Производительность
- **Границы server/client:** `'use client'` поднят слишком высоко по дереву — в бандл уезжает то,
  что могло остаться на сервере. Клиентским должен быть лист, а не layout.
- **Водопады запросов:** последовательные `await fetch` там, где нужен `Promise.all`; фетч в
  `useEffect` вместо серверного компонента.
- **Кэширование:** осознанный выбор `cache`/`revalidate`/`force-dynamic`; отсутствие `revalidate`
  на данных, которые обязаны быть свежими, и наоборот — `force-dynamic` там, где хватило бы ISR.
- **Картинки:** `next/image` вместо `<img>`; заданы `width`/`height` или `fill` + `sizes`
  (иначе CLS); осмысленный `priority` только для LCP-элемента.
- **Бандл:** новые тяжёлые зависимости; `next/dynamic` для редко используемых тяжёлых компонентов;
  импорт всей библиотеки вместо конкретного модуля.
- **Ре-рендеры (клиент):** нестабильные пропсы/колбэки в списках, тяжёлые вычисления в рендере
  без `useMemo`, подписка на весь стор вместо среза.
- Шрифты — через `next/font` (без layout shift и внешнего запроса).

### Качество и упрощение
- Лишний `useEffect` для производных данных; `useState` + `useEffect` для синхронизации с пропсом.
- Данные тянутся в клиентском компоненте там, где хватило бы серверного.
- Роут-файлы тонкие: логика в `lib/`, а не в `page.tsx`.
- Типизация пропсов и ответов API; нет `any`; `zod`-схемы (или аналог) на границе ввода.
- Нет дублирования разметки — общие примитивы UI; повторяющаяся логика → хук.
- Нет мёртвого кода, закомментированных блоков, `console.log`.

### Дизайн-система
- Цвета/отступы/радиусы — из токенов (CSS-переменные, `tailwind.config`, тема), не хардкод hex
  в компонентах.
- Переиспользование общих UI-примитивов вместо самописных дублей.
- Тёмная/светлая тема — через токены, а не ветвление хардкодом в компоненте.
- Пользовательский текст — через i18n-словари, если в проекте есть i18n; новые ключи во все локали.
- Форматирование денег/дат — общий хелпер, не `toFixed` и не конкатенация в JSX.
