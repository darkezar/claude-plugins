# Картридж: React SPA

Подключается, когда в `dependencies` есть `react`, но **нет** `next` и `react-native`.
Сборщик (Vite / CRA / Webpack), роутер и стор определи по `package.json` — не предполагай.

Главное отличие от Next.js: **весь код клиентский**. Сервера в проекте нет, поэтому любая
проверка прав здесь — только UX; авторитет живёт в API, который ревьюится отдельно.

## Тулинг

```bash
npx tsc --noEmit    # типы, если TypeScript
npm run lint
npm run build       # ловит ошибки сборки и показывает размер бандла
npm run test        # если настроены тесты
```

Сверься с реальными скриптами в `package.json` перед запуском.

## Триггеры условных ревьюеров

**auth** — пути: `src/auth/**`, `src/routes/**`, `ProtectedRoute*`, `src/api/**`, `src/store/*auth*`,
`src/hooks/useAuth*`, интерцепторы HTTP-клиента.
Слова в дифе: `localStorage`, `sessionStorage`, `token`, `jwt`, `Bearer`, `Authorization`,
`ProtectedRoute`, `Navigate`, `redirect`, `refreshToken`, `logout`, `role`, `permission`.

**performance** — слова в дифе: `useEffect` с фетчем, `useMemo`/`useCallback`, `.map(` по большим
массивам, `<img`, `lazy(`/`Suspense`, новые зависимости в `package.json`, контекст-провайдеры
вокруг больших поддеревьев, `JSON.parse`/`sort`/`filter` в рендере.

## Привязки чек-листа

### Безопасность
- **В бандле нет секретов.** Всё, что попало в `import.meta.env.VITE_*` / `REACT_APP_*`,
  публично и извлекаемо. Серверные ключи, секреты платёжек, админ-токены — только на бэкенде.
- **Токены в `localStorage` доступны любому XSS.** Предпочтительно — `httpOnly`-cookie, выдаваемая
  сервером. Если токен всё же в `localStorage`/`sessionStorage`, это осознанный компромисс:
  флагай и требуй, чтобы он был описан, а не случаен.
- `dangerouslySetInnerHTML` на пользовательских данных без санитизации.
- Открытый редирект: переход по URL из query (`?next=`, `?returnTo=`) без allowlist.
- Секреты и PII не попадают в `console.log`, в URL и в аналитику.
- Только HTTPS в базовом URL API; нет отключения проверки TLS.
- Новые зависимости: репутация, размер, постустановочные скрипты.

### Авторизация и доступ
- **Клиентский гейт — это UX, не защита.** `<ProtectedRoute>`, скрытие кнопки, `if (role === ...)`
  в JSX не защищают данные: их обходят DevTools'ом. Флагай любой комментарий/формулировку,
  где такой гейт назван защитой.
- Каждое чувствительное действие должно проверяться сервером; клиент только инициирует.
- Клиент не отправляет на сервер то, что сервер обязан вычислить сам (суммы, цены, роли, статусы).
- Роли/права не разбросаны хардкодом по компонентам — централизованный хелпер, а решение на сервере.
- Обновление токена: refresh без гонок (один запрос на много параллельных 401), корректный
  logout — токен отзывается на сервере, а не только чистится локально.
- Форма логина: `autoComplete`/`type` заданы верно, пароль не живёт в стейте дольше нужного.

### Производительность
- **Ре-рендеры:** подписка на весь стор/контекст вместо среза; новый объект/массив/функция
  в пропсах на каждый рендер; провайдер контекста с меняющимся `value` вокруг большого поддерева.
- **Списки:** `key={index}` на переупорядочиваемых данных; отсутствие виртуализации на длинных
  списках (react-window/react-virtual); тяжёлый `renderItem` без мемоизации.
- **Вычисления в рендере:** `sort`/`filter`/`reduce` по большим массивам, парсинг, форматирование
  без `useMemo`.
- **Водопады запросов:** последовательные `await` там, где нужен `Promise.all`; фетч в дочернем
  компоненте после фетча в родителе.
- **Бандл:** `React.lazy` + `Suspense` для тяжёлых роутов; импорт конкретного модуля вместо всей
  библиотеки; проверь прирост размера после `npm run build`.
- **Картинки:** заданы размеры (нет CLS), `loading="lazy"` для внеэкранных, разумный формат/размер.
- Эффекты: таймеры, слушатели, подписки, `AbortController` — снимаются в cleanup.

### Качество и упрощение
- Лишний `useEffect` для производных данных — считать при рендере.
- `useState` + `useEffect` для синхронизации с пропсом/стором — вычислять из источника.
- Логика фетчинга размазана по компонентам вместо слоя `src/api` / query-библиотеки.
- Компоненты тонкие: данные и состояние отдельно от разметки; длинный JSX разбит на под-компоненты.
- Типизация пропсов и ответов API; нет `any`/`as any`; валидация ответа на границе.
- Нет дублирования — общие примитивы UI, общие хуки, общие хелперы.
- Нет мёртвого кода, закомментированных блоков, `console.log`.

### Дизайн-система
- Цвета/отступы/радиусы — из токенов (CSS-переменные, конфиг Tailwind, тема), не хардкод hex
  в компонентах.
- Переиспользование общих UI-примитивов (кнопка, поле, модалка) вместо самописных дублей.
- Тёмная/светлая тема — через токены, а не ветвление хардкодом.
- Пользовательский текст — через i18n-словари, если i18n есть; ключи во все локали.
- Деньги/даты — через общий хелпер форматирования.
