# Картридж: Expo / React Native

Подключается, когда в `dependencies` есть `expo` или `react-native`. Версии Expo SDK и RN возьми
из `package.json` и сверяйся с ними: API между мажорами заметно меняется. Если проект на голом RN
без Expo — пункты про `expo-*` пакеты применяй только при их фактическом наличии.

## Тулинг

```bash
npx tsc --noEmit    # типы (strict, если включён)
npx expo lint       # если настроен; иначе точечно npx eslint <file>
```

Запускать из каталога приложения. Здесь **нет** `npm run build` и веб-сборки — не вызывай их.

## Триггеры условных ревьюеров

**auth** — пути: экраны логина/OTP/сканера, `**/store/*auth*`, `**/api/**`, `app/_layout.tsx`
и layout'ы с гейтами, обработчики deep link.
Слова в дифе: `SecureStore`, `AsyncStorage`, `token`, `Bearer`, `Authorization`, `authed`,
`Redirect`, `login(`, `logout(`, `useLocalSearchParams`, `Linking`, `scan`, `qr`, `permission`.

**performance** — слова в дифе: `FlatList`, `ScrollView`, `FlashList`, `map(` по большим массивам,
`reanimated`, `useSharedValue`, `Animated`, `Image`, `expo-image`, `useMemo`/`useCallback`,
`setInterval`/`setTimeout`, подписки, новые тяжёлые зависимости.

## Привязки чек-листа

### Безопасность
- **Токены — только в `expo-secure-store`, никогда в `AsyncStorage`.** Отдельно проверь
  `persist`-конфиг стора (`partialize`/whitelist): на диск должны уходить только настройки.
  Токен в persist — это тот же AsyncStorage.
- **Клиентский бандл извлекаем.** Любой ключ в коде приложения достаётся из сборки. Допустимы
  только публичные значения (URL API, publishable-ключи); серверные секреты — нет.
- Deep links и результат сканирования — недоверенный ввод: валидируй по allowlist, не выполняй
  чувствительное действие напрямую по параметру ссылки.
- Логи: `console.log` с токенами, OTP, PII, платёжными данными — они остаются в сборке.
- В git не попадают `.env`, `google-services.json`, `GoogleService-Info.plist`, `credentials/`,
  `*.p8`, `*.p12`, `*.pem`, `*.mobileprovision`, `keystore`.
- Только HTTPS в сетевом слое; нет отключения проверки сертификата.
- Данные карт: только токен шлюза, бренд и последние 4 цифры; PAN/CVV не хранить и не логировать.

### Авторизация и доступ
- **Гейт expo-router — это UX-навигация, не защита.** `<Redirect href="/login" />` при `!authed`
  улучшает поток, но не защищает данные. Флагай формулировки, где такой редирект назван защитой.
- Чувствительные действия (оплата, изменение чужих данных, физические действия вроде открытия
  замка) выполняет сервер по серверному подтверждению; клиент только инициирует и показывает результат.
- Клиент не отправляет на сервер вычисленные им суммы/цены/статусы — сервер считает сам.
- IDOR: экран запрашивает ресурс по `id` из параметров — сервер обязан проверять владельца;
  в клиенте не должно быть логики «чужой id не подставят».
- Токен уходит в заголовке `Authorization`, не в query-параметре.
- Logout чистит SecureStore и отзывает токен на сервере.
- Поля ввода: `secureTextEntry` для пароля, корректные `autoComplete`/`textContentType`
  (`oneTimeCode` для OTP, `telephoneNumber`, `emailAddress`).

### Производительность
- **Списки:** длинные и динамические — через `@shopify/flash-list`, не `ScrollView` + `.map()`
  и не `FlatList`. Стабильный `keyExtractor` (id, не индекс), `renderItem` и сепаратор вынесены
  в module scope (инлайновая стрелка ломает рециклинг ячеек).
- **Ре-рендеры:** гранулярные селекторы стора (`useStore(s => s.x)`), а не подписка на весь стор;
  нестабильные инлайн-объекты/колбэки в пропсах ячеек списка; тикающее значение (таймер, счётчик)
  вынесено в маленький мемоизированный лист-компонент, а не перерисовывает весь экран.
- **Анимации:** `react-native-reanimated` на UI-потоке (`useSharedValue`/`useAnimatedStyle`),
  анимируются `transform`/`opacity`, а не layout-свойства (`width`, `height`, `top`, отступы).
  `setState` покадрово — дефект.
- **Картинки:** `expo-image` (кэш, плейсхолдер, приоритет) вместо сырого `Image`; фиксированные
  размеры контейнера (нет скачка layout); не грузить полноразмерные изображения в ячейки списка.
- **JS-поток:** нет тяжёлой синхронной работы в рендере и в обработчиках жестов; тяжёлые
  вычисления мемоизированы или вынесены.
- **Утечки:** таймеры, слушатели (`AppState`, `Linking`, `Keyboard`), подписки realtime и
  анимации снимаются в cleanup эффекта.
- Тяжёлые тени и `BlurView` в ячейках списка и часто перерисовываемых областях — по стоимости.

### Качество и упрощение
- Нет лишних `useEffect` для производных данных; корректные deps; `exhaustive-deps` не отключён без причины.
- Иммутабельные обновления состояния; бизнес-логика в сторе/`lib`, а не размазана по экранам.
- Экраны тонкие: в файлах роутов — композиция, логика в отдельных модулях.
- TypeScript strict: нет `any`/`as any`, пропсы типизированы, доменные типы не дублируются.
- Переиспользуются общие UI-примитивы вместо самописных дублей.
- Нет мёртвого кода, закомментированных блоков и `console.log`.
- Нет веб-наследия: `className`, `.module.scss`, `var(--...)`, CSS-`transition`, `backdrop-filter`,
  `prefers-color-scheme` — в React Native этого не существует.

### Дизайн-система
- Цвета — из типизированной темы через хук темы; **хардкод hex/rgb в компонентах запрещён**.
  Допустимы: сам файл палитры, стоп-точки градиентов, верные макету, и фиксированные контрастные
  цвета «поверх медиа» (белый/чёрный текст, полупрозрачные подложки на цветной обложке).
- Новые цвета добавляются в **обе** схемы (light/dark) в палитре; компонент не ветвится на тему сам.
- Текст — через общий текстовый примитив, не сырой `<Text>`; иконки — через общую обёртку,
  не прямой импорт иконочного сета.
- Стили — `StyleSheet.create` или инлайн-объекты; никаких утилити-классов (NativeWind, если его
  нет в зависимостях). Отступы и радиусы — числа RN, не CSS-строки.
- Тени — строкой `boxShadow` (New Architecture), значение из темы.
- **Пользовательский текст — только через i18n-словари**, ключи добавлены во все локали.
- Деньги и даты — через общий хелпер форматирования, не ручной конкатенацией и `toFixed`.
