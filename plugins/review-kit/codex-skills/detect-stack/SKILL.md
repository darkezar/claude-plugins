# База сравнения и стеки в Codex

Прочитай применимые правила проекта. Верни базовый репозиторий/remote, `BASE_BRANCH`,
`BASE_SHA`, `HEAD_SHA`, `BASE` (merge-base), приложения и их картриджи. Это обнаружение
контекста, без переключения веток, исправлений, коммитов и публикации.

## База

1. Для переданного PR используй его `baseRefName`, `baseRefOid`, `headRefName`, `headRefOid`
   и репозиторий из `gh pr view`. Сначала сверь репозиторий; номер PR нельзя применять
   к другому checkout. Для ветки с открытым PR возьми базу этого PR, если пользователь
   не указал иную базу явно. Падение `gh` не доказывает отсутствие PR — укажи ограничение.
2. Иначе используй явно заданную базу, затем доступный remote HEAD базового репозитория.
   По `git remote -v` учти `upstream` в форках; не предполагается, что remote всегда origin.
   При сети обнови нужные refs. Если явно задан SHA, зафиксируй его и не подменяй свежей
   вершиной ветки. Без сети укажи, что используются локальные refs.
3. Если remote HEAD недоступен, проверь существующие `main`, `master`, `develop`, `trunk`.
   Единственный кандидат допустим как явно отмеченный fallback; несколько кандидатов
   требуют данных о целевой ветке, а не выбора первого по порядку.
4. Разреши существующие commit SHA через `git rev-parse --verify` и найди `git merge-base`.
   Не хардкодь `main`. При отсутствии HEAD или общей базы верни отсутствие сравнения:
   ревью может проверить доступные staged/unstaged/untracked, а `ship` должен отдельно
   определить целевую базу перед созданием PR.

## Стеки

Алгоритм маркеров, исключения служебных манифестов и таблица пяти стеков общие:
прочитай **только «Шаг 2. Активные стеки»** из
[исходного detect-stack](../../skills/detect-stack/SKILL.md). Его shell-fallback выбора
первой существующей ветки не используй: базу определяет раздел выше.

В монорепозитории верни несколько приложений с их путями; для ревью подключи картриджи
только затронутых приложений. Учитывай `dependencies` и `devDependencies` реальных
приложений. Next.js исключает React SPA, Expo/RN используют один картридж.
Legacy-часть без маркеров получает универсальный чек-лист, а не стек соседнего приложения.

Читай подходящие навыки: [Laravel](../stack-laravel/SKILL.md),
[Yii2](../stack-yii2/SKILL.md), [Next.js](../stack-nextjs/SKILL.md),
[React SPA](../stack-react-spa/SKILL.md), [Expo/RN](../stack-expo-rn/SKILL.md).
Версии бери из манифестов. Команды проверок подтверждай конфигурацией проекта,
передавай исполнителю точный рабочий каталог, команду и ограничения среды.
