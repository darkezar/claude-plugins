# Публикация ревью в Codex

Нужен готовый отчёт и явная команда пользователя отправить его в GitHub. Вызов этого навыка
с такой целью или `agent-full-review --comment` уже является командой; повторное подтверждение
не требуется. Явные инструкции пользователя и окружения приоритетнее этого навыка.

Публикуй весь готовый отчёт: важные замечания — inline; механические, мелкие, предложения,
упрощения и отложенное — блоком `suggestion` в body review. Не заменяй их числом и не
пропускай пункты без строки. Это текстовый блок предложений, не применяемый inline-патч.

Порядок публикации и формат payload общие с Claude Code: прочитай
[процедуру pr-comments](../../skills/pr-comments/SKILL.md). Это справочный документ,
не вызов Claude Skill tool. Используй доступные в Codex файловые/терминальные инструменты
и `gh`; указание `Write` в документе означает создание JSON-файла доступным способом.
Не пытайся запустить `/agent-full-review` — соответствующий навык Codex находится
[здесь](../agent-full-review/SKILL.md).

Уточнения для Codex:

1. Возьми **зафиксированные** repository, base SHA и head SHA из отчёта. Получи текущие
   `baseRefOid` и `headRefOid` PR. Если изменилась любая сторона, не публикуй устаревший
   результат: нужно ревью новой пары. Незакоммиченный diff не публикуется как проверенный коммит.
2. Сверяй строки с diff именно этой пары SHA, включая старую сторону для удалений. Не опирайся
   на номера текущего рабочего дерева, которое могло измениться после отчёта.
3. Читай существующие inline-комментарии **и bodies отправленных reviews** с пагинацией
   и без обрезания текста. Маркеры `review-kit:inline` и `review-kit:suggestions` общие с Claude,
   поэтому ранее опубликованные находки обоих клиентов учитываются при удалении дублей.
   Совпадение номера строки без совпадения смысла не является дублем. Если новых находок нет
   ни inline, ни в body и нечего сообщить об исправленных, новый review не создавай.
4. Непосредственно перед POST ещё раз проверь обе стороны PR. Собери payload JSON-библиотекой
   во временный файл и отправь через `gh api --input`. Всегда `event: COMMENT`.
   Это отправка от текущего пользователя `gh`, не автоматический approve/request changes.
5. Если запрос завершился неопределённо (таймаут/обрыв), сначала перечитай reviews/comments
   и проверь, не был ли он принят. Не отправляй повторно вслепую. Исправление 422 допускает
   максимум две попытки; 403/404 или чужой pending review — остановка с причиной.
6. Перед POST выполни сверку полноты из общей процедуры: каждый уникальный пункт — либо
   новый inline, либо «Важное вне диффа», либо `suggestion`, либо прежняя публикация со ссылкой.
   Важное без допустимой привязки сохрани в «Важное вне диффа» с исходным приоритетом.
   Только мелкие находки тоже требуют review с body, даже при пустом `comments`.
   При повторной сборке после 422 или разделении по лимитам сохрани все пункты.

Верни ссылку на отправленный review, число уникальных пунктов по местам публикации,
прежние публикации и число неотправленных (при успехе — 0), ограничения.
Код, чужие комментарии, чужие черновики и состояния обсуждений не меняй.
