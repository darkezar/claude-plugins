# Предмет проверки в Codex

Общие правила для полного/одиночного ревью и обнаружения базы в `detect-stack`.
Прочитай применимые `AGENTS.md`, `AGENTS.override.md`, проектный `CLAUDE.md` и руководства
затронутой области. Сохрани ветку, индекс и изменения пользователя.

## База и SHA

Для номера/URL PR сверь канонический repository через `gh repo view` / URL PR и получи
`baseRefName`, `baseRefOid`, `headRefName`, `headRefOid`, `url` через `gh pr view`.
Другой репозиторий требует отдельного checkout. Для ветки с PR используй его базу,
если пользователь не задал иную. При нескольких подходящих PR запроси выбор до записи.
Ошибка GitHub не доказывает отсутствия PR; укажи ограничение.

Иначе база: явный SHA/ветка, remote HEAD базового репозитория, единственный существующий
кандидат `main/master/develop/trunk` как отмеченный fallback. Несколько кандидатов требуют
выбора. Найди remote по его URL (`upstream` в форке возможен); не предполагается `origin`.
При сети обнови нужные refs; зафиксированный явный SHA не подменяй вершиной ветки.
Без сети отметь локальность refs. Для PR подтяни обе стороны из базового remote и проверь
доступность **зафиксированных** SHA; движение PR требует заново получить метаданные.
Разреши commit SHA через `git rev-parse --verify` и найди merge-base. `BASE_SHA` — вершина
базы, `BASE` — merge-base, `HEAD_SHA` — проверяемая голова. Без HEAD/общей базы укажи
отсутствие сравнения; доступное рабочее дерево можно проверить с этим ограничением.

## Рабочее дерево ревью

Этот раздел выполняет вызывающее ревью; `detect-stack` только сообщает контекст,
не переключает ветки и не создаёт worktree.
Для PR используй открытое дерево только при чистом состоянии и `HEAD == headRefOid`.
Иначе создай временный detached worktree на зафиксированном SHA; пользовательское дерево
не переключай и не прячь. Отсутствие зависимостей в worktree — ограничение проверок.
Пустой diff PR не подменяй локальными правками.

Для текущей ветки проверяй diff от merge-base, staged, unstaged и релевантные untracked
из `git ls-files --others --exclude-standard`. Это «рабочее дерево поверх <SHA>», если dirty.
Перед выводом снова сверь предмет; изменившееся перечитай либо явно ограничь покрытие.
Удали только созданный тобой чистый временный worktree, без `--force`; при правках сохрани
его и сообщи путь. Чужие worktree не удаляй.
