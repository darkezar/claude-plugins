# workflow-gate

Ворота на инструмент `Workflow`. Фан-аут агентов разворачивается только тогда, когда его
действительно попросили, — в остальных случаях Клод делает задачу обычным способом.

## Зачем

Режим ultracode велит разворачивать workflow почти на любую содержательную задачу. Это
удобно ровно до первого счёта: разбор расхода за месяц показал, что три четверти трат на
помощников приходились на фан-аут, которого никто не просил.

Цифры, ради которых всё это написано:

- шаг агента впятеро дешевле шага ассистента, но запусков много;
- медианный workflow стоит как **97** шагов ассистента, самый мелкий на 2–3 агента — как **48**;
- медианная задача решается ассистентом за **9** шагов, и лишь 5% задач доходят до 97.

То есть фан-аут окупается только на действительно крупной работе. Плагин возвращает это
решение человеку, не отключая возможность.

## Как решает

| Условие | Решение |
|---|---|
| Открыт временный пропуск `~/.claude/workflow-allow` | разрешить, судью не звать |
| Всё остальное | решает судья, и его вердикт окончателен |

**Судья** — отдельная дешёвая сессия (`claude -p`, Sonnet, около трёх центов за вызов). Ему
показывают последние сообщения пользователя и паспорт предлагаемого запуска: имя, описание,
число фаз и вызовов `agent()`. Он отвечает одной строкой JSON. Судья недоступен, ответил
невнятно или не уложился в 45 секунд — отказ.

Явная просьба («разверни агентов») и вызов слэш-команды **не открывают ворота сами по себе**.
Они передаются судье как сведения, и он взвешивает их вместе с остальным. Причина: признак
ловится по трём последним сообщениям, поэтому сказанное для одной задачи открывало ворота и
для следующей, уже другой. Судья может отклонить и прямую просьбу — тогда продавить можно
только пропуском.

Если такая жёсткость не нужна, замени в `hooks/workflow-guard.py` ветку с `judge.ask(...)`
на прежнее короткое замыкание по `asked`/`slash` — обе переменные там уже посчитаны.

Отказ ничего не ломает: это `permissionDecision: deny` с объяснением, Клод просто делает
задачу сам. Ночные прогоны из-за ворот не встают.

Из сессии самого судьи фан-аут запрещён наглухо — иначе ворота могли бы звать сами себя.

## Установка

```bash
/plugin marketplace add darkezar/claude-plugins
/plugin install workflow-gate@darkezar
```

Всё. Хук ставится вместе с плагином, руками в `settings.json` лезть не нужно.

Нужен `python3` в `PATH` и команда `claude` — та же, которой запускается сам Claude Code.

## Обновление

Установка копирует плагин в `~/.claude/plugins/cache/<каталог>/<плагин>/<версия>/`, поэтому
правки в репозитории сами по себе никуда не доезжают — **даже если каталог локальный**.
Порядок такой:

1. поправил файлы в `plugins/workflow-gate/`;
2. поднял `version` в `.claude-plugin/plugin.json` — без этого `/plugin update` ответит
   «already at the latest version» и ничего не сделает;
3. `/plugin marketplace update <каталог>` — подтянуть сам каталог;
4. `/plugin update workflow-gate@<каталог>` — забрать новую версию;
5. перезапустить сессию: хуки читаются при старте.

## Что добавить в свой CLAUDE.md

Плагин не может дописать в твой `~/.claude/CLAUDE.md` — это твой файл. Ворота работают и
без этого, но с текстом ниже Клод перестаёт даже пытаться развернуть агентов на мелочи, и
ты видишь вердикт, когда он был:

```markdown
## Когда разворачивать workflow и субагентов

По умолчанию workflow не разворачивается. Разбор расхода показал, что три четверти трат на
помощников приходились на фан-аут, которого никто не просил.

Но и спрашивать разрешение на каждый подходящий случай не надо. Владелец хочет, чтобы
агенты разворачивались **сами, по нужде**: подходит случай под список ниже — запускай,
решение принимают ворота. Не подходит — делай обычным способом и не поднимай вопрос.

Фан-аут оправдан только в одном из случаев:

- пользователь попросил словами («разверни агентов», «сделай workflow», «параллельно»)
  или вызвал слэш-команду, скилл которой сам этого требует;
- работа физически не помещается в один контекст: правки в десятках мест, миграция по
  всему проекту, аудит большого куска кода;
- нужна независимая перепроверка находок несколькими взглядами, и цена ошибки высока —
  деньги, права доступа, необратимые операции.

Фан-аут не нужен: ответить на вопрос, найти файл или причину ошибки, починить один баг,
влить ветку, прогнать тесты, разобраться в одном модуле, написать фичу в пределах
нескольких файлов. Это делается обычным способом.

Перед запуском назови одной строкой, зачем нужен фан-аут и сколько примерно агентов.
Не можешь внятно назвать причину — значит он не нужен.

Это правило сильнее осторожности харнесса. Описание инструмента Workflow велит на любой
неоднозначный случай не запускать, а спрашивать словами; здесь наоборот — если случай
попадает в список выше, запускай сам и не задавай вопрос. Вопрос уместен только когда
ворота отказали, а ты считаешь, что они ошиблись.

То же по инструменту Agent, но мягче: один-два помощника для поиска по большому
репозиторию — нормально, шесть параллельных ревьюеров на мелкую правку — нет.

Ворота (плагин `workflow-gate`) проверяют каждый запуск. Решает судья
(модель Sonnet, около трёх центов за вызов): ему показывают задачу и паспорт
предлагаемого workflow, и его вердикт окончателен. Судья недоступен или ответил
невнятно — отказ.

**Просьба владельца больше не открывает ворота сама по себе.** Слова «разверни агентов»
и вызов слэш-команды уходят судье как сведения, он взвешивает их вместе с существом
задачи и вправе отказать даже прямой просьбе. Это осознанное решение, а не недосмотр: см. README плагина.

Отсюда обязанность: **если ворота отклонили то, о чём владелец попросил словами, скажи
ему об этом первой строкой ответа и приведи причину отказа**. Иначе он ждёт агентов,
не получает их и не понимает почему.

Отказ — не повод спорить или искать обход: сделай задачу обычным способом. Единственный
способ продавить — временный пропуск `/workflow-pass <часов>`; при нём судью не зовут
вовсе. Предлагай его, когда уверен, что судья ошибся. Разрешение ворот — потолок, а не
команда: если задача решается без агентов, агенты не запускаются.

## Отчёт о решении по workflow

Строка нужна только тогда, когда ворота **реально сработали**: ты попытался запустить
workflow и его разрешили или отклонили. Тогда — первой строкой ответа, до содержательной
части, одна строка без подробностей:

`Workflow: запущен, N агентов — <зачем>`
`Workflow: отказано судьёй — «<причина из вердикта>»`

Во всех остальных случаях строки быть не должно. Не отчитывайся о том, что фан-аут не
понадобился, и не объясняй, почему задача обычная, — это шум, а не информация.

Точную формулировку вердикта бери из ответа ворот или из последней строки
`~/.claude/workflow-guard.log`, не пересказывай по памяти.
```

## Временный пропуск

Когда работа правда крупная и отказы мешают:

```
/workflow-pass 3      # открыть на 3 часа (без аргумента — 2)
/workflow-pass        # состояние и последние решения ворот
```

Закрывается сам. Попросить закрыть раньше — тоже через этот скилл.

## Настройки

Переменные окружения, если поведение по умолчанию не подходит:

| Переменная | Что делает |
|---|---|
| `WORKFLOW_GATE_JUDGE=off` | не звать судью, отказывать сразу — бесплатно, но грубее |
| `WORKFLOW_JUDGE_MODEL` | модель судьи, по умолчанию `claude-sonnet-5` |
| `WORKFLOW_JUDGE_TIMEOUT` | сколько ждать судью, по умолчанию 45 секунд |

## Журнал

Каждое решение пишется строкой в `~/.claude/workflow-guard.log`:

```
2026-09-23 11:48:02	deny	судья: задача решается в одном контексте	inline-script
2026-09-23 12:10:44	allow	явная просьба	review-changes
```

Полезно раз в неделю посмотреть, что ворота отклонили, — если там есть задачи, которые ты
и правда хотел развернуть, стоит подправить формулировки в своих просьбах.

## Чего плагин не делает

- Не трогает инструмент `Agent` — один-два помощника для поиска остаются доступными
  всегда. Ограничение на них живёт только в тексте `CLAUDE.md` выше.
- Не считает токены и не следит за лимитом. Это ворота на решение, а не бюджет.
- Не мешает слэш-командам: если скилл команды сам требует фан-аута, ворота его пропускают.
