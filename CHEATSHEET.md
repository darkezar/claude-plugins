# Памятка

Что набирать и когда. Полное описание устройства — в [README](README.md).

## Установка на новой машине

```bash
/plugin marketplace add darkezar/claude-plugins
/plugin install review-kit@darkezar
/plugin install tooling-kit@darkezar
/plugin install context-kit@darkezar
/plugin install debug-kit@darkezar
/plugin install upgrade-kit@darkezar
/plugin install git-kit@darkezar
/plugin install explain-kit@darkezar
```

Ставится один раз, работает во всех проектах на машине. Управление — `/plugin`.
Обновить после правок в репозитории:

```bash
/plugin marketplace update            # подтянуть каталог
/plugin update review-kit@darkezar    # обновить плагин — имя обязательно с @каталогом
```

## Все команды

| Команда | Плагин | Когда |
|---|---|---|
| `/agent-full-review` | review-kit | **Перед PR.** Главная команда |
| `/ship` | review-kit | Ветка → проверки → коммит → push → PR |
| `/review` | review-kit | Нужно быстро и дёшево, глубина не важна |
| `/apply-fixes` | review-kit | После ревью — применить правки |
| `/branch-review` `/security-review` `/auth-review` `/performance-review` `/design-review` `/simplify-review` | review-kit | Нужен ровно один ревьюер |
| `/i18n-sync` | review-kit | Сверить и починить словари локализации |
| `/test` `/lint` `/typecheck` `/fmt` | tooling-kit | Прогнать то, что реально настроено в проекте |
| `/git-state` | git-kit | «Где я и что подвисло» — ветка, незакоммиченное, забытые ветки, стеши |
| `/explain` | explain-kit | Отчёт непонятен или слишком длинный — пересказать с вариантами решения |
| `/debug` | debug-kit | Есть баг, нужна причина |
| `/context-init` | context-kit | В проекте нет `CLAUDE.md` |
| `/context-refresh` | context-kit | `CLAUDE.md` разошёлся с реальностью |
| `/upgrade-check` | upgrade-kit | Пора разобраться с зависимостями |
| `/detect-stack` `/detect-tooling` | служебные | Обычно вызываются сами |

## Аргументы `/agent-full-review`

| Аргумент | Что делает |
|---|---|
| *(без аргументов)* | Сам решает, какие ревьюеры нужны под этот дифф |
| `all` | Все шестеро принудительно |
| `min` | Только код-ревью |
| `security,auth` | Ровно перечисленные |
| `--fix` | После отчёта перейти к правкам |

Комбинируются: `/agent-full-review all --fix`.

## Типовые сценарии

### Начало сессии — «а где я вообще»

```
/git-state
```

Ветка, незакоммиченное, забытые ветки, стеши. Дальше предложит действия по пунктам —
делает только то, что подтвердишь. Ничего разрушительного по своей инициативе не выполняет.

### Обычный цикл работы

```
… пишешь код …
/agent-full-review          # отчёт: что не так
/agent-full-review --fix    # или сразу с правками
/ship                       # коммит, push, PR
```

`--fix` применит механическое сразу, а по остальному покажет развилки: проблема, пример как она
стреляет, варианты, рекомендация. Выбираешь ты.

### Пришёл баг

```
/debug бронь исчезает через 15 минут после создания
```

Даст симптом → воспроизведение → причину с коммитами → варианты починки. Разбор ложится
в описание PR почти как есть: `/ship` для багфиксов сам предложит формат «Симптом / Причина».

### Первый заход в незнакомый проект

```
/context-init        # собрать CLAUDE.md — спросит то, чего нет в коде
/detect-tooling      # узнать, как тут запускаются тесты
/agent-full-review   # посмотреть на текущую ветку
```

### Обновление зависимостей

```
/upgrade-check              # отчёт и план по шагам
… обновляешь один шаг …
/test                       # автоматическая проверка
/agent-full-review          # обновление часто меняет поведение незаметно
… проверяешь руками сценарии из плана …
```

По одному мажору за коммит. Два в одном — и при поломке не поймёшь, который виноват.

### Отчёт непонятен или его слишком много

```
/explain
```

Без аргумента возьмёт последний отчёт этой сессии. Можно указать текст, файл или номер PR:
`/explain 171`.

По каждому пункту: что не так двумя строками, конкретный случай почему это плохо, варианты
таблицей с ценой каждого, и какой выбрал бы он — с причиной. Сверху строка «если чинить
только одно». Вкусовщина уезжает в «можно не чинить», а не в разбор.

Ничего не правит и серьёзность не меняет: если в отчёте «критично», в пересказе тоже
будет «критично».

### Только безопасность, быстро

```
/security-review
```

## Чего эти команды принципиально не делают

Понимание границ экономит время на споры с инструментом.

- **Ревьюеры не правят код.** У них нет `Edit` и `Write`. Правит отдельный агент после отчёта.
- **Безопасность и логика не чинятся молча.** Только через развилку, где решаешь ты.
  Тихо неверно закрытая дыра хуже незакрытой: с неё снимается внимание.
- **Перевод не выдумывается.** Ключи добавляются во все локали, значения-заглушки помечаются
  как требующие перевода.
- **`CLAUDE.md` не правится фоном.** Он в контексте каждой сессии, и молчаливая порча
  была бы невидимой.
- **Прогон инструментов не имитируется.** Не удалось запустить — так и будет написано,
  с причиной. Никаких «тесты прошли» без запуска.
- **`/upgrade-check` не обновляет.** Он даёт план; проверяют тесты и ты.
- **`/explain` не чинит и не смягчает.** Это перевод отчёта, а не второе мнение о нём:
  ярлыки серьёзности сохраняются, новые проблемы не ищутся. Не согласен с исходным
  отчётом — скажет отдельно, а не перепишет вывод молча.

## Стоимость

~4 500 токенов в каждой сессии на все семь плагинов — это оглавление. Содержимое конкретной
команды или скилла грузится только при вызове.

Прогон агентов стоит по-настоящему: они читают файлы целиком. Поэтому оркестратор сначала
решает, кто нужен, и на мелкой правке не разворачивает фан-аут. Если ревью кажется избыточным
для задачи — `/review` вместо `/agent-full-review`.

## Если что-то не так

| Симптом | Причина |
|---|---|
| Команд нет в списке `/` | Плагин поставлен после старта сессии — перезапусти |
| Ревью смотрит не ту ветку | Проверь, на какой ветке стоишь: сравнение идёт с базовой |
| «Тесты не запущены» | Нет доступа к окружению — `/detect-tooling` покажет, чего не хватает |
| Ревьюер не запустился | Оркестратор решил, что его тема не затронута; причина есть в отчёте. Форсировать — `all` |
| Правки не применились | Незакоммиченные изменения в дереве — предупредит до начала |
